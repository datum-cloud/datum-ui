# Type Scale

The typography ramp built from the type tokens.

The rules for sizing text in Datum UI. One named scale is shared by raw Tailwind
classes and the `Typography` components, so `text-sm` and `<Text size="sm">`
always render the same size.

## Rules

1. **Named steps only.** Use `text-sm`, `text-xs`, `text-2xs`, … — never an
   arbitrary size like `text-[11px]`. A size only exists if it's a step in the
   scale. Changing a size is a one-line edit to a theme token, not a find-and-replace.
2. **One scale for classes and components.** `Text`, `Paragraph`, and `Title`
   render these same steps. A raw utility class and the component always agree.
3. **Body sizes are fixed; display sizes step down.** `5xs`–`lg` are the same on
   every screen (dense UI text must not shrink on phones). `xl` and larger step
   down one notch per breakpoint — using existing steps, so no new values appear.

## Naming

Steps below `xs` mirror the `2xl` / `3xl` convention **downward**:

`5xs` · `4xs` · `3xs` · `2xs` · `xs` · `sm` · `base` · `lg` · `xl` · `2xl` … `8xl`

There is no `1xs` — just as there is no `1xl`. The step directly below `xs` is
`2xs`, then `3xs`, then `4xs`, then `5xs`. Smaller number closer to `xs`; larger number =
smaller text.

## The scale

Desktop values, in px (`font-size` / `line-height`).

### Body — fixed on every screen

Reach for `5xs` only where 9px already earns its place; `4xs` is the smallest
size meant for text a reader parses rather than glances at.

## Using it

`Text` adds no line height of its own — each step carries the one paired with
it in the theme — so the component and the utility render identically. Pass a
`leading-*` class for a different rhythm. `Paragraph` is the exception: its
`spacing` prop defaults to `leading-relaxed` for prose blocks.

Raw utilities and the component are interchangeable:

```tsx
// Raw Tailwind utility
<span className="text-2xs text-muted-foreground">Updated 2m ago</span>

// Typography component — same step, same rendered size
<Text size="2xs" textColor="muted">Updated 2m ago</Text>
```

`Title` levels map to display steps and handle their own responsiveness — do
**not** add `md:` / `lg:` size classes on top, or headings shrink twice.

A heading below 14px is not a heading — use `<Text as="h4">` for a micro label
that must stay in the outline.

`level` picks the size and the element together. Where the document outline and
the visual size disagree, `as` decouples them: `<Title as="h2" level={5}>` is an
`h2` rendered at 18px.

## Color

Size and color are separate choices. `Text` and `Title` **inherit** their
parent's color unless you set `textColor`, just like a raw `<span>` or `<h4>`.
Top-level text still renders in the foreground color because `body` sets it,
and text inside an alert, badge or muted container follows that container.

When a color is needed, use a semantic token, never a raw palette color like
`text-green-600`:

## How it's defined

The scale is `--text-*` theme variables in `alpha.css` (Tailwind v4 `@theme`).
Consumers import that stylesheet and get the utilities for free.

```css
@theme {
  --text-5xs:  9px;  --text-5xs--line-height: 12px;
  --text-4xs: 10px;  --text-4xs--line-height: 14px;
  --text-3xs: 11px;  --text-3xs--line-height: 16px;
  --text-2xs: 12px;  --text-2xs--line-height: 16px;
  --text-xs:  13px;  --text-xs--line-height:  18px;
  --text-sm:  14px;  --text-sm--line-height:  20px;
  /* base … 8xl: desktop values */
}
```

Tailwind generates a `text-<name>` utility for every `--text-*` variable — no
plugin, no config. Each utility applies its paired `--text-<name>--line-height`
by default, and a `leading-*` class still overrides it, exactly like the
built-in sizes.

The display steps shrink by redefining the same variables in media queries
(`width < 64rem` for tablet, `width < 48rem` for mobile). That only works
because the scale is a plain `@theme`, not `@theme inline`: the utilities read
`var(--text-*)` at runtime instead of baking in the desktop value.
